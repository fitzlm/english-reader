# LinguiPro：原网页点词翻译与静读滚动修复

## 目标与保存位置

实现两项改动：

1. 在已开启功能的网站上，单击普通英文正文，在单词旁显示中文释义。
2. 修复静读滚到底部后继续下滚时，底部露出原网页的问题。

**状态：2026-09-27 已实施完成（8def669 / bf5fb89 / 46aeef2 / e8018a3 / 版本 1.1.0 文档与打包），待人工验收（见文末）。** 本文件即计划与执行清单，不另拆 plan.md / todo.md。

## 评审修订（已确认）

- 图标改弹出菜单；右键菜单与 ⌥⇧R 保持一步打开静读。原网页点词与阅读页一致，调用 `update-word` 记录查词。
- 授权：popup 同步调用 `permissions.request`，同时把待开启站点告诉后台；真正开启（注册脚本、补注入）在后台 `permissions.onAdded` 与消息处理中幂等完成，不依赖 popup 存活。
- 内容脚本：注册一个普通加载脚本 `src/page/loader.js`，用 `import(chrome.runtime.getURL(...))` 动态加载点词模块；相关模块加入 `web_accessible_resources`，不复制 `shared/text.js`。
- 孤儿脚本：新实例启动时通知旧实例卸载；旧实例发现 `chrome.runtime.id` 失效时自行停用。
- 静读底色放在淡入的 iframe 上（随 `ready` 与主题切换消息同步），不放宿主，保留淡入；根治靠 `overscroll-behavior-y: none`。
- 双击：`event.detail ≥ 2` 时关闭词卡并丢弃在途结果。
- 测试：开启流程用预授权地址走真实链路；拒绝授权替换 `permissions.request`；撤销直接调后台处理函数；重启用固定用户目录重开浏览器；原生授权提示放人工验收。
- README 隐私一节同步更新；版本升至 1.1.0。

### 内部消息约定

| 方向 | 消息 | 响应 |
|---|---|---|
| 页面 → 后台 | `{type:'lp-page-lookup', word}` | `{word, form, lemma, phonetic, defs, gloss, source:'dict'\|'mt'}` 或 `{error, status}` |
| popup → 后台 | `{type:'lp-site-status', tabId}` | `{supported, origin, enabled, granted}` |
| popup → 后台 | `{type:'lp-site-enable', origin, tabId}` / `{type:'lp-site-disable', origin}` | `{enabled}` 或 `{error}` |
| popup → 后台 | `{type:'lp-open-reader', tabId}` | `{ok}` |
| 后台 → 页面 | `{type:'lp-page-lookup-stop'}` | — |

站点列表存 `chrome.storage.local.pageLookupSites`（origin 字符串数组，如 `https://example.com`）；内容脚本注册 id 为 `lp-page-lookup`。

## 一、原网页点词翻译

### 启用入口与站点状态

- 点击插件图标打开菜单，包含“本站点词翻译”开关、“打开静读”和“设置”；原有右键打开静读及快捷键继续可用。
- 默认关闭。用户开启时请求当前网站权限，授权成功后立即生效；拒绝授权则保持关闭并说明原因。
- 站点设置存入 `chrome.storage.local`，按协议和精确主机名记忆，不自动覆盖其他子域；刷新、再次访问和浏览器重启后保持生效。
- 使用持久注册的内容脚本，并为已打开的同站页面补充注入。关闭时注销脚本，并通知现有页面移除词卡、停止监听；浏览器撤销权限时同步停用。
- 后台启动和扩展更新时核对设置、权限及脚本注册状态，避免重复注入。此方案使用 Chrome 的[动态内容脚本注册](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)和[可选权限](https://developer.chrome.com/docs/extensions/reference/api/permissions)。

### 点击与词卡行为

- 首版支持桌面 Chrome 普通 HTTP/HTTPS 网页的顶层正文，包括动态加载的文字；采用事件委托，不扫描或改写整篇网页。
- 参考现有阅读页的坐标取词算法，验证点击确实落在单词范围内；沿用英文撇号、词形规整和长度限制，连字符词按现有规则分开查询。
- 排除链接、按钮、表单控件、可编辑区域、代码及明确的交互控件；拖选、双击选词、修饰键点击不触发查词，不取消原网页的正常点击事件。
- 不可靠的跨文本节点单词命中直接跳过，避免把片段误当完整单词。iframe、Shadow DOM 内部文字、图片、Canvas、PDF 和浏览器内置页不纳入首版支持范围。
- 词卡采用 Shadow DOM 隔离样式，显示原词、词典释义或机翻结果及来源；不增加发音、收藏、认识了或 AI 语境释义功能。
- 词卡限制在可视区域内，空间不足时向上展开；长内容内部滚动。点击外部、按 Esc、原网页滚动或窗口大小变化时关闭。
- 打开静读时关闭原网页词卡并暂停点词响应，关闭静读后恢复。

### 翻译与内部接口

- 网页脚本通过扩展消息请求后台查词；鉴权和网络请求留在后台，复用现有游客及账号逻辑。
- 查询顺序为单词词库查询，再对缺词请求现有机器翻译接口；只发送用户点击的词，不上传整篇网页。
- 新增内部查词消息、站点状态控制消息，以及词卡关闭／停用通知；后台验证发送页面所属站点、启用状态和单词格式，消息不接受任意请求 URL。
- 缓存成功结果并合并重复查询；缓存随后台生命周期存在，切换账号或服务器时清空。
- 每次点击生成新的查询序号，旧响应不能覆盖新词或重新打开已关闭的词卡。请求中显示加载状态，失败显示原因和重试入口。
- 无需新增后端接口或数据库迁移。

## 二、静读底部露出原网页修复

### 已知事实与复现

当前阅读层宿主及 iframe 背景透明，阅读页只在 `html` 上设置 `overscroll-behavior: contain`，原网页仅锁定 `html` 的 overflow。

**初步原因是边界回弹叠加透明背景，尚未完成运行时复现。** `contain` 会保留自身回弹；iframe 内的滚动边界应在其文档的 `html/body` 上控制。[相关浏览器行为](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overscroll-behavior)

先用长文章复现到底后连续下滚，记录阅读页和原网页滚动位置、阅读层边界及底部画面，区分回弹露底与原网页滚动穿透。

### 修复方案

- 在阅读页 `html/body` 设置纵向 `overscroll-behavior-y: none`，禁止上下边界回弹及纵向滚动传递。
- 阅读层宿主及 iframe 使用不透明背景，与阅读页主题同步；通过现有 iframe 消息通道传递实际背景色，并继续验证消息来源。
- 将阅读层宿主挂到文档根节点，避免原网页 `body` 的 transform 等样式改变固定定位范围；确保覆盖整个视口。
- 阅读层显示期间锁定原网页 `html/body` 的滚动，并保存修改前的相关行内样式、优先级和滚动位置。关闭后恢复这些值及原焦点。
- 连续打开、快速关闭和替换阅读层时，清理定时器、监听器和滚动锁，防止遗留锁定。
- 保留阅读页正常滚动、段落定位、词卡内部滚动及设置面板操作；不通过全局吞掉滚轮事件修复问题。

## 三、实施顺序与验收

| 阶段 | 工作与依赖 | 验收条件 |
|---|---|---|
| 1 | 复现并修复静读滚动问题，补回归测试 | 到底继续下滚不露出原网页，原网页位置不变；关闭后恢复滚动、样式和焦点 |
| 2 | 实现后台查词服务及结果状态处理 | 词典、缺词机翻、重复请求、失败重试和旧响应处理正确 |
| 3 | 接入原网页取词与词卡，依赖阶段 2 | 单击正文可查词；排除区域、拖选和原网页交互正常 |
| 4 | 接入插件菜单、站点授权及持久启用，依赖阶段 3 | 授权后立即生效，刷新及重启后保持，关闭或撤权后停止 |
| 5 | 集成验收、使用说明和打包 | 两项功能及已有阅读流程通过检查，生成可加载的扩展包 |

实施时可由独立子代理处理滚动修复；点词功能由另一代理按依赖顺序完成。主代理负责消息接口约定、共享文件协调、关键改动审查和最终验收。

**自动化检查**

- 执行 `npm test`、针对新功能的 Playwright 测试、完整 `npm run e2e`，最后执行 `npm run package`。
- 点词测试覆盖词典命中、机翻、短词、撇号、标点与空白、拖选、交互区域排除、动态正文、屏幕边缘词卡、连续点击和关闭后的迟到响应。
- 站点测试覆盖首次开启、拒绝授权、多个同站标签页、刷新、重启、关闭、权限撤销和重复注入。
- 滚动测试覆盖长文底部连续滚轮、顶部反向滚轮、普通页面、body 滚动页面及 transformed body；检查原网页位置、阅读层覆盖范围和关闭后的恢复。
- 现有测试夹具预先授予本地网站权限，不能作为真实授权流程的唯一证据；补充未预授权场景，并在真实 Chrome 中检查权限提示。

**人工验收**

- macOS Chrome 中使用触控板惯性滚动验证“到底继续下滚”原始问题；自动化滚轮通过不能替代这项检查。
- 检查浅色、深色主题和窗口缩放下不露底，阅读层关闭后原网页可正常操作。
- 在普通文章、动态加载正文及带交互控件的页面试用点词，确认原有静读入口及阅读页查词没有回归。
